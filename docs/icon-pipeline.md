# 图标流水线

应用图标的唯一设计源是 `logo/512x512.png`——一张黑底的像素「Ready」字标。派生素材全部由脚本生成，**不要手改**生成出来的文件：

```powershell
pwsh -File tools/make-icons.ps1
```

## 约束：不裁切

脚本**不裁切**：把整幅原图等比缩放后铺进方形画布，空出来的部分用作品自带的黑底补满。

`Inset`（原图占画布的比例）在代码里被断言为 `(0, 1]`，超过 1 就说明要把原图的边角推出画布，脚本会直接失败——「不裁切」是硬约束，不是注释里的约定。

## 产物

| 产物 | 画布 | 原图占画布 | 底色 | 用途 |
| --- | --- | --- | --- | --- |
| `src/Ready/Resources/AppIcon/appicon.png` | 1024 | 0.923 | 透明（整幅抠黑成 alpha） | Android 自适应图标的前景层 + 单色层 |
| `src/Ready/Resources/Splash/splash.png` | 512 | 1.000 | 不透明黑 | Android 启动屏 |
| `src/Ready.WinForms/Assets/appicon.ico` | 16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256 | 1.000 | 不透明黑 | Windows 窗体、任务栏与托盘 |
| `src/Ready/wwwroot/brand/appicon.png` | 256 | 1.000 | 不透明黑 | 浏览器标签页图标（界面内不再使用） |

## 为什么字标只占画布 66.6%

因为不裁切，字标在这些图里最大只能占画布宽的 **66.6%**——它在原图里就只占这么多，再放大就必须切掉左右黑边。这是取舍的代价，也是 16px 帧上字标只有约 11×4px、会糊成一条发光色带的原因。

## 为什么 Android 那档单独缩到 0.923

字标的四个角离画布中心有 `0.3596 × 边长`，而 Android 各厂商遮罩（圆形、方圆、圆角方）只保证半径 `0.3335 × 边长` 的圆内可见。

`0.3335 / 0.3596 ≈ 0.927`，再留 0.5% 余量给整数像素的取整误差，得到 0.923——脚本每次都会按实测值重算，不是写死的常数。空出来的面积由同色黑补满，所以画面看着还是原图，只是退了一点点。

## 为什么前景层要透明底

APP 图标的前景层必须是透明底，否则 Android 13+ 的主题图标（monochrome 层）会拿它当剪影，渲染成一整块黑饼。

所以这一张会把黑底按亮度反预乘成 alpha（`a = max(R,G,B)`，颜色再除以 `a` 还原）；源图最外圈的最大通道值实测为 0，抠掉黑底不会截断任何辉光。

> 不要直接把 `logo/` 里的原图引用成 `MauiIcon`：那是不透明黑底，会盖住自适应图标的底色层，而且没有为安全圆留过缩放，圆形遮罩下会切掉字标的两端。
